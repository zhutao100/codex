# Responses Output Replay

Use `codex --enable output_token_replay` or set `output_token_replay = true` under `[features]` before starting a session. The feature is under development and off by default. It requests an opaque representation of sampled output from OpenAI so full input can more closely reproduce a healthy [WebSocket continuation](responses-websocket.md). It cannot recover fields that were previously discarded, force the endpoint to supply replay data, or guarantee a prompt-cache hit.

## Request and History Contract

|Destination|Ask for new `output.encrypted_content`|Send previously received sampled-output ciphertext|
|---|---|---|
|OpenAI, flag on|Yes, independently of the model's reasoning-summary setting.|Yes.|
|OpenAI, flag off|No.|Yes, including after resume.|
|Other provider, either flag|No.|No. Filter only the outbound copy, including compaction; keep the original in history.|

The [wire types](../../protocol/src/models.rs) retain optional ciphertext on assistant messages and function, custom tool, local shell and hosted search calls. They also retain message/function status and output-text annotations/logprobs, distinguishing absent from empty arrays. Preserve returned values; never invent a search result from its query. Prior reasoning/compaction ciphertext, the legacy server-item ID policy, tool-call IDs and ordered tool results are separate contracts. The opt-in does not enable server storage or change the reasoning include on non-reasoning models.

Ciphertext consumes wire and rollout bytes, but is not another copy of visible prompt text for local budgeting. Memory extraction omits top-level ciphertext. A retained message rewritten during compaction must not claim the original sampled text's replay data.

## Diagnosing a Drop

- For a new run set `CODEX_TRACE_PROMPT_CACHE=1` and `RUST_LOG=off,codex_core::cache_trace=debug`. This cache-only filter includes `provider cache receipt`, `completed logical cache comparison` and `reasoning replay report`, without enabling normal tool argument/result logs. It applies to newly emitted records, not preexisting log contents or the conversation rollout. The opt-in is independent of output replay. Join by response ID, keep parent and reviewer threads separate and compare against both the previous completion and the last ordinary work. Diagnostic baselines do not survive process restart.
- `shared_items` counts equal projected input items against the baseline input **and its output**; it is not a token count. `sibling_suffix` means all work up to the notes marker matched: retries and rejected calls after it are not ordinary work. A mismatch before the marker is still a changed prefix. Other shapes distinguish an extension, a changed input/output, a settings change and newly installed history. `changed_surface` identifies the first differing endpoint, model, base message, ordered tools or generation controls. The trace includes operation, outer stream attempt, transport decision, idle time, sampled-output replay coverage and accounted usage. It does not observe auth/routing, provider-side rendering or cache residency.
- `cached_tokens_reported=false` means no usable provider count, not a measured zero. Use actual reported cached tokens and uncached tokens by transition rather than treating new suffixes or compacted replacements as avoidable misses. An extension with low reuse is an unexplained provider outcome unless further evidence identifies the cause. The receipt records a provider cache comparison result if supplied; this client does not inject unsupported comparison parameters into a request.
- `attempt` counts outer stream attempts. For a completed HTTP stream, `http_retries` counts additional HTTP sends within that attempt, including authentication recovery. A WebSocket 426 followed by HTTP has `transport_reason="websocket_upgrade_required"`; later HTTP sends on that fallback have `sticky_websocket_fallback`. `http_fallback_cause` distinguishes an upgrade failure from exhausted stream retries. Direct HTTP has no fallback cause, and WebSocket completions have no HTTP retry count. These fields explain the delivery path, not the provider's cache decision.
- `storage` reports the effective wire policy: `Disabled`, `Enabled`, or `AzureStoredIds`. The trace compares the actual `store` flag and fingerprints the item IDs that the [Azure HTTP builder](../../codex-api/src/requests/responses.rs) attaches, without logging those IDs. A fallback from a non-storing WebSocket to Azure's default HTTP policy is a settings change even if the transcript is unchanged. Later HTTP requests with the same projection can extend one another normally.
- The [comparison implementation](../../core/src/client/cache_trace.rs) retains keyed item signatures for at most the last completion and ordinary baseline between requests, not prompts, tool results or ciphertext. With tracing disabled it does not hash inputs. With tracing enabled a full send hashes the logical input; a validated WebSocket delta reuses the verified prefix signatures. Do not use this trace as a recovery checkpoint.
- Operation describes the request's purpose, not its tool permissions. An explorer's report-only request updates the ordinary work baseline; notes capture does not. Both reject tool execution.
- `codex.websocket.continuation` counts WS send attempts (including failed sends), not successful completions. `mode` distinguishes `full` from `incremental`; `reason` distinguishes initial/restored history, a closed connection, missing response state, changed request properties, and shortened or mismatched item prefixes. Mismatch labels contain only item types. This transport sends generation requests, not upstream's history-bearing warmup requests.
- `codex.responses.reasoning_replay` counts completed response reports: unavailable, no reported removals, prefix mismatch, or other removals. `codex.responses.reasoning_items_removed` records a histogram per bounded reason, including zeros for usable arrays. Missing, null or non-array reports produce no histogram. An unknown/missing removal reason maps to `other`; non-reasoning entries and non-removal actions do not count. The sampling step supplies the metric tags; this release has no `product_sku` metadata to attach.
- Use transport and completion evidence together. A full replay can hit the prompt cache; a removal report alone does not prove a reconnect. Do not retry successful inference, edit history, or change compaction policy based on either metric.

## Verification

The [replay fixtures](../../core/tests/suite/output_token_replay.rs) exercise provider filtering, resume and reconnect. The [cache trace fixture](../../core/tests/cache_trace.rs) runs ordinary work, notes, compact and resumed work over both HTTP and WebSocket; it injects cold usage for an unchanged prefix and a sibling, distinguishing missing cache details from reported zero. The [metrics fixture](../../otel/tests/suite/snapshot.rs) checks removal reports. A hosted cache claim requires a separate live comparison at the same completed boundary.
