# Streaming-compaction validation

Count all model POSTs in the [review budget fixture](../../../core/tests/suite/completion_review_wire_budget.rs). A preflighted review with impossible fixed costs sends neither helper; ordinary capacity compaction does not promise this. For structured work, compare live and recovered V2's tools with the outgoing request and the replacement's tools with the new policy. [Ordinary-loop tests](../../../core/src/session/live_review_dispatch_tests.rs) exercise a budget between embedded and separate advice, an unaffordable or wrong-route handoff with no durable deferral, steering and a return to the original endpoint. [Helper transport tests](../../../core/src/session/live_helper_route_tests.rs) compare the tool result and route-bound controls. These checks establish request eligibility, not hosted cache hits.

Select tests by the affected contract. The linked suites are regression entry points, not a statement that a particular build or deployment has passed them.

## Focused commands

```bash
CODEX_SANDBOX_NETWORK_DISABLED=1 cargo-local test -p codex-core --lib compact -- --test-threads=2
CODEX_SANDBOX_NETWORK_DISABLED=1 cargo-local test -p codex-core --test all compact_remote_v2 -- --test-threads=2
```

Use shared wrappers and the existing `skip_if_no_network_unless_localhost!` guard for mock transport. Let the wrapper supply its loopback capability. Do not count an early-return network guard as transport execution. Select `compaction_mode = "unary"` in unary fixtures; the default for an eligible provider exercises a different request/response contract.

Regenerate the affected config/protocol artifacts only when their source schemas change. Expand to related suites when changing shared output handling, usage accounting, pause/resume or task-stop behavior.

## High-value interaction cases

- Reject notes at the context limit without usage, then install a paid V2 result. Cut the recorder at `Compacted` and check cumulative input and cached input through the first ordinary completion. For a paid but unusable V2 result instead, retry `/compact` live and after restart; compare intact helper inputs, the ordinary measurement and the structured request sent by `/continue`.
- [Ordinary capacity](../../../core/tests/suite/compact_remote_v2_ordinary_pressure.rs): after installation and a tool result without usage, straddle the transmitted cost of a paired result, not its larger stored cost. Check live and restart with tools and schema included exactly once. Add and drop a large response format on another model and on a rebound endpoint behind the same slug. A completed task's old bill cannot size the destination; an unfinished source may still owe a checkpoint.
- [Ordinary transitions](../../../core/tests/suite/compact_remote_v2_capacity_transitions.rs): add and remove a queued MCP inventory across the threshold, then cut at an unmeasured tool result that takes its source over the limit. Check the smaller local destination separately. For an ordinary context rejection, first accumulate more paid input than one full window; compare billed and cached totals across refusal, restart, installation and an endpoint change. The [steering fixture](../../../core/tests/suite/pending_input.rs) compares the full helper and ordinary requests across a downshift after the owed tool result, including which directory's policy reached MCP first.
- [Refused request routing](../../../core/tests/suite/compact_remote_v2_refused_route.rs): complete work on A, have B refuse a fresh prompt, and capture every POST. Compare notes and trigger prefixes to B's request; A must never see that input. Cover HTTP opening and streamed failures, with and without schema, restart on A, and standalone `/compact` before `/continue`. At the recorder cut before the refusal ledger, the admitted prompt still belongs to B. Change login while returning a 400 in the [authenticated route fixture](../../../core/src/session/live_helper_route_tests.rs).
- Notes in commentary followed by reasoning and empty/whitespace final output; compare the entire emitted note with follow-up and replay, including text after the closing tag.
- Multipart output with split sentinels/code and plan tags on separate lines; same-line tags do not exercise the plan parser.
- Rejected tool outputs after notes, interruption before rejection recording, and later acknowledged user input outside the bounded capture.
- Failed local summarization attempts followed by Continue/new input and restart; failed output must be absent from recovery requests and replacements.
- Downshift notes reporting little usage, followed by failure/pause and a new recovery destination; compaction still uses the original source while replacement fits the destination. Hold a helper open, refuse a competing manual start, then interrupt the retry. Verify the actual continuation ID, source requests and first ordinary model/schema with a different startup model. A wrong-directory refusal sends no helpers and leaves review recovery unchanged.
- Compare uninterrupted and restarted requests after fresh acceptance, the notes marker and answer, a positive below-trigger compact receipt, installation and each prompt/context/skill write. For a selected checkpoint, also compare `/compact` followed by `/continue`: only the remaining helpers precede that continuation. Assert ordered input, tools, model and schema. Vary mode/CWD before admission, startup instruction size and the settings of an old response that must finish before a new task.
- Compare helpers with the last **ordinary** request. Grow and shrink the destination base across the review limit without changing the work. Sample a second model, refresh its catalog, and restart at fresh acceptance, an ordinary tool result before the decision, and tagged notes. Verify destination settings after installation. Fork at a tagged call with a typed-only connector and admit a fresh prompt directly and after restarting the child; compare ordered tools, and check the new thread's base-message ID separately from its content.
- Replay an older rollout containing a worktree snapshot; check it does not become model input.
- A real recorder blocked after memory replacement, stopped through actual pause/interrupt handlers; stopping must wait for installation. Read the durable file without a test-side flush and replay it.
- Long retained notes and local recomputation after restart; the notes must not be charged twice or trigger a spurious repeat compaction.
- Queue `/compact` across `TurnComplete`, ahead of the [reserved reviewer or continuation](../../../core/src/codex_thread.rs); verify one successor and no maintenance request. Cancel the reservation and verify maintenance can run. At a mandatory review stop after installation, a wrong-directory command must not sample or change review state; return to the owning directory and complete recovery.

## Evidence limits

Local fixtures establish client routing, request shape, state ordering and replay. They do not establish model summary quality, server cache hits, server latency or deployed support for every model/provider. Use [native acceptance](native_acceptance.md) for a synthetic deployed-endpoint check and report it separately. Retention remains approximate and cannot predict arbitrary input appended after pre-turn compaction.
