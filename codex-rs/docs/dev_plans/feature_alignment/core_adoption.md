# Select core alignment work

Status: proposed selection under [feature alignment](README.md). Apply [project principles](../../principles.md): the harness owns completion, tools, context and recovery; request prefixes and opaque data are contracts; transport state is not durable history. A new reference feature row is a discovery lead, not evidence that its capability is missing here.

### Terminal writes

Current [`write_stdin`](../../../core/src/tools/handlers/unified_exec.rs) forwards process ID, bytes, wait and output budget; [`process_manager.rs`](../../../core/src/unified_exec/process_manager.rs) writes nonempty bytes after its PTY check. Current [`ProcessEntry`](../../../core/src/unified_exec/mod.rs) lacks the reference's retained authority/environment snapshot. Reference [stdin approval](https://github.com/zhutao100/codex/blob/33411a01d7dae5fe89728ecfa2ab8b1c09002329/codex-rs/core/src/unified_exec/stdin_approval.rs#L187) exempts empty polls and compares authority before a nonempty write; [a57b398351a8](https://github.com/zhutao100/codex/commit/a57b398351a803c9ec94e38042bc82f527bed2a4) also records identity revalidation after approval.

Keep the current single-environment design unless another workstream needs multiple environments. Preserve process handles, PTY/pipe behavior, output-range receipts and owned-job lifetime. The broader `exec_permission_approvals` and `request_permissions_tool` are optional API expansions: if selected, their argument schemas, permission merging and runtime enforcement must arrive together.

### Existing context correctness to retain

Current [`compact_remote_v2_history.rs`](../../../core/src/compact_remote_v2_history.rs) already charges image cost and preserves atomic labels. [`compact_remote_v2.rs`](../../../core/src/compact_remote_v2.rs) reserves destination instructions, tools, compaction output and exact work notes before allocating retained input. The reference's newer original-detail image policy is not a correction for absent accounting here.

`unified_image_budget` is a broader model/protocol expansion. The [reference gate](https://github.com/zhutao100/codex/blob/33411a01d7dae5fe89728ecfa2ab8b1c09002329/codex-rs/core/src/image_preparation.rs#L81) requires the feature plus Responses Lite or model support for original-detail images. Its larger image policy and detail-aware accounting must be adopted together. Defer until those routes/models are supported and a quality/cost requirement exists; no benefit was measured for the current branch.

Current [`run_sampling_request`](../../../core/src/session/turn.rs) already keeps one tool router across prompt construction and dispatch. The [reference `StepContext`](https://github.com/zhutao100/codex/blob/33411a01d7dae5fe89728ecfa2ab8b1c09002329/codex-rs/core/src/session/step_context.rs#L33) additionally owns exact MCP connections/catalog and environment snapshots. Current MCP calls still use the session manager; this difference matters if catalog refresh becomes concurrent with an in-flight request. Establish that interleaving before proposing a wholesale context-owner rewrite.

If adopting `untrusted_as_tool_output`, first support standalone named tool outputs in the normalizer, durable history and renderer. Otherwise orphan-output cleanup can discard valid contextual content. Keep exact user-request provenance separate. For `reasoning_effort_override` and tool-baseline preservation, retain append-only settings updates without rewriting initial instructions or opaque replay data.

### Recovery policy

`unbounded_connection_retries` is scoped, despite its name. [Reference selection](https://github.com/zhutao100/codex/blob/33411a01d7dae5fe89728ecfa2ab8b1c09002329/codex-rs/core/src/responses_retry.rs#L102) requires eligible sampling connection failures and excludes internal sessions and Bedrock. Keep cancellation authoritative; do not turn authentication, validation, budget or arbitrary server errors into unlimited retries. A completion-review delegate must not inherit an indefinite policy merely because the parent uses it.

The WebSocket fixes [bb5b9c624013](https://github.com/openai/codex/commit/bb5b9c6240136de8ff4d30215e2341c44559aa04), [9f2b87495bf9](https://github.com/zhutao100/codex/commit/9f2b87495bf979f6c1953cf00c98143981664914) and [1c297f899](https://github.com/zhutao100/codex/commit/1c297f899) concern blocked uploads, peer replies and control-frame progress. Compare their transport owner with this branch before porting; these useful changes are invisible to a registry-only comparison.

For speculative compaction, capture/register work before releasing its ownership lock, separate foreground-turn cancellation from session shutdown, reject stale candidates and charge completed speculative usage even when discarded. Reconcile all of these with custom pause and durable review before launching background work. Do not enable async compaction and token-budget rollover as two competing policies.

For Multi-agent V2, preserve max depth/concurrency, child model/provider selection, explicit paused-parent continuation, no idle/superseded-owner sampling from saved job results, and exact notification/input ordering. `interrupt_on_cancel` is separately limited to Responses Lite with an interrupt-capable stream; local cancellation must finish for every provider. General multi-agent capabilities do not automatically belong in completion-review delegates or bounded explorers.

## Defer product surfaces by default

Desktop browser/annotation/computer-use/voice/dictation gates, hosted connector metadata, runtime identities, enterprise/PSP integration, Chronicle, image generation, native artifacts, billing/analytics UI and setup wizards are not prerequisites for this branch's core agent loop. Their registry entries can remain absent until the branch hosts the corresponding workflow.

Guardian families evaluate approval decisions. They do not replace custom post-turn completion review. Their explicit tool-policy ceilings may inform reviewer/explorer construction, but any automatic-approval product remains separately scoped.

`view_image` illustrates a new flag around an existing capability: this branch already checks model image modality and registers the handler. Do not add a redundant flag to claim a new tool. TUI conveniences, daemon autostart and `prevent_idle_sleep` can be valuable independent work; the reference sleep prevention is attached to TUI turn lifecycle, so adopting it does not by itself prove custom `codexd`/completion-review coverage.

Already retired reference registry entries are not adoption targets. Useful behavior that became unconditional must be assessed at its owner; a Removed label alone does not prove every related implementation vanished. The full per-key relevance classification and Git provenance live in the accompanying research inventory so this active plan remains focused on decisions.
