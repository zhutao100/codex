When you see this instruction, you're in a customized fork repo branch.

# Changes convention

Changes in this branch are drop-in diff commits staying on top of the upstream branch.

When an upstream refresh is explicitly requested, use `git pull --rebase origin main` to replay the fork commits on upstream. Plain `git pull origin main` does not itself request a rebase; do not refresh upstream implicitly during feature work.

Thus, the design of the changes target to minimize the potentials of future rebase conflicts.

# Agents operation tips

- Always use the shared `cargo-local` wrapper instead of direct `cargo` for local build/check/test/run commands. It uses an external target dir when an agent-created `/Volumes/*/.codex-rs-build-root` marker directory is mounted, and otherwise falls back to the workspace `target/`. Keep its per-worktree target separation when building comparison baselines.
- Use `just-local` instead of direct `just` in Rust projects whose recipes call `cargo` directly; it adds a per-invocation `cargo` shim that delegates to `cargo-local`.
- always use `CODEX_SANDBOX_NETWORK_DISABLED=1` for test runs to avoid tampering the host.
- With `CODEX_SANDBOX_NETWORK_DISABLED=1` on macOS, `cargo-local` wraps Cargo in a Seatbelt profile that allows localhost sockets only and filters tests listed in `scripts/cargo-local-network-sandbox-skips.txt` because they exercise nested sandbox/shell behavior.
- `cargo-local test` defaults to agent output: it filters passing libtest progress, passing-test subprocess chatter, and legacy snapshot notices into a compact summary while preserving warnings and failures. Prefer `-- --show-output` for diagnostic output while retaining repository test exclusions; the shared wrapper's `CODEX_RS_CARGO_LOCAL_TEST_OUTPUT=raw` mode currently bypasses those exclusions.
- The `cargo build` commands can produce giant console output, even with `--quiet`. Redirect broad/noisy build output to tmp files and parse only necessary information.
- For mock-only HTTP/WebSocket tests, use the existing `skip_if_no_network_unless_localhost!` guard. Let the wrapper declare localhost capability; never forge its flag or count an early-return network test as executed transport coverage.
- Keep model discovery's compile-time version override, `/models` query, and cache identity aligned; see [model client version](docs/model_client_version.md). Strip both prerelease and build metadata.
- Refresh bundled models from the server cache without dumping prompts; see [bundled models](docs/features/bundled_models.md). Keep offline presets catalog-derived and thread naming, Explorer, and rate-limit selectors on supported models.
- See [streaming remote compaction](docs/features/remote_compaction_v2/README.md) before changing compaction, work notes, replay or client continuation. Keep triggers request-only, notes/snapshots exact, and installation coherent with task cancellation. Explicit unary fixtures must disable `RemoteCompactionV2`.
- Compaction recovery must preserve acknowledged input beyond a bounded notes capture and remain consistent in task finalization and rollout replay. Accept matching rejected tool outputs after notes, and leave capture cleanup to recovery. Background snapshot writes share the installation guard; previous-model compaction must resolve that model's provider and effective instructions.
- Keep compaction source/request and destination/replacement contexts separate across failure and restart; notes usage cannot identify a pending downshift. Recover multipart notes with exact assistant output-text concatenation. Validate installation cancellation with a real recorder, actual task-stop handlers and replay, without a test-side flush after task-stop.
- Output helpers must honor sampling's capture-specific plan-parsing decision; test plan tags on separate lines. Local summarization output stays private to its attempt until completion so failed attempts cannot corrupt notes recovery.
- See [completion review](docs/features/post_turn_completion_review/README.md) before changing review capture, advisory continuation or review replay. Keep frozen consumed scope and initial/latest answer slots separate from prompt history, capture the returned terminal answer, and require complete replacement finals even under custom reviewer prompts.
- Reserve a manual completion review's candidate snapshot and ticket together after joining task finalization; delegate entry must validate the ticket against both the supplied snapshot and live state. Keep prepared/started handoffs durable, and preserve versioned metadata in rollout readers and continuation cleanup; `ResponseItem::Message.id` is not serialized and cannot identify a persisted advisory.
- Enforce the latest candidate's exact CWD when preparing, claiming or resuming review-derived main work, including pause and replay. Reject mismatches before taking the pending checkpoint or starting a task. Every replacement candidate must capture its actual completed `TurnContext` CWD, not retain the initial answer's directory or adopt a later configuration-only change. A recognized amendment body must retain the now-ineligible prior candidate as its directory owner across the missing `Recorded` snapshot boundary.
- Only a new root session or trusted review metadata establishes exact request provenance. Missing/unsupported metadata or discarded history stays unavailable even when compaction leaves no visible user boundaries; later referential input cannot restore missing context.
- Persist original accepted input and a revision-specific installation marker before its model-facing body; persist consumption only after that body is durable. Recover unrecorded acknowledgements as well as body-written/flag-not-written gaps, and never deduplicate distinct identical amendments by text found elsewhere in history.
- Rollout flush/shutdown acknowledgements must carry the I/O result. Test actual buffered-write faults through review/continue handlers, including paused and compacted Started handoffs. Propagate each resumed-owner write failure before sampling; missing mandatory snapshots must be an error, never ordinary no-review context. Preserve checkpoints and the last good recovery prefix.
- Keep running task handles alive through completion persistence. Serialize registration and externally requested pause/interrupt/shutdown with finalization even after its active-task entry is removed; only then may shutdown detach the recorder. Join completion-review installations before publishing stopped state; explicit pause/interrupt/shutdown also invalidate queued automatic work. Test these boundaries with a real recorder and replay, without a test-side flush after stop.
- Exercise advertised budget recovery with actual `/compact` or model selection followed by `/continue`, not snapshot-only tests. Compaction must retain the pending owner, and stop/shutdown must retain started main handoffs. Retarget an explicit regular-model selection in both the pending checkpoint and durable handoff, even if already selected in session settings. Preserve selection intent from the submitted model/collaboration-mode fields; modes synthesized for CWD, approval or effort-only updates must not retarget recovery. Do not change frozen snapshots, paused reviewer ownership or the notes capture's source model.
- Human clarification answers need durable question/answer ownership or explicitly unavailable review coverage; arbitrary tool-output JSON is not genuine request provenance. Keep scripted transport coverage separate from live behavioral evaluations. Native prompt overrides use `ConfigToml.model_instructions_file`; `Config.base_instructions` is a programmatic override, not a TOML option.
- See [local plugins](docs/features/local_plugins.md) for the minimal local skills/MCP backport. Keep installation separate from execution, preserve qualified skill mentions and MCP requirements filtering, and verify release binaries with the VM-only `scripts/verify-local-plugins.py`; do not migrate the direct-core TUI to app-server for this feature.
- Keep plugin-selected skills out of the shared cwd cache. Forced skill listings and turn lookups must apply the caller's effective config so session overrides remain aligned with MCP activation.
